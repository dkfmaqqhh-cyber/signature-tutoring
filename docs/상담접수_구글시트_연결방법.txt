====================================================================
 시그니처과외 상담 신청서 → Google Sheets 연결 방법 (14.5차)
====================================================================

관련 파일
 - docs/google-apps-script-consult.js : Google Apps Script에 붙여 넣을 코드
 - js/script.js (맨 위)                : CONSULT_API_URL 에 웹 앱 주소 입력
 - consult.html                        : 상담 신청서 (수정할 필요 없음)

현재 상태
 - CONSULT_API_URL 이 기본값("YOUR_GOOGLE_APPS_SCRIPT_WEB_APP_URL")이면
   신청서를 제출해도 아무 데이터도 전송하지 않고
   "상담 접수 주소가 아직 연결되지 않았습니다" 안내만 표시합니다.
 - 아래 1~6단계를 마치면 실제 접수가 시작됩니다.


--------------------------------------------------------------------
1단계. 구글 스프레드시트 만들기
--------------------------------------------------------------------
 1) 상담 접수용으로 사용할 구글 계정으로 https://sheets.google.com 접속
 2) [빈 스프레드시트] 새로 만들기 → 이름 예: "시그니처과외 상담접수"
 3) 주소창의 URL에서 스프레드시트 ID를 복사해 둡니다.
      https://docs.google.com/spreadsheets/d/【이 부분이 ID】/edit
 ※ 시트 탭 이름이나 헤더는 직접 만들 필요 없습니다.
    첫 접수 때 '상담접수' 시트와 헤더 행이 자동으로 만들어집니다.
 ※ 이 스프레드시트는 개인정보가 담기므로 다른 사람과 공유하지 마세요.


--------------------------------------------------------------------
2단계. Apps Script 코드 붙여 넣기
--------------------------------------------------------------------
 1) 스프레드시트 상단 메뉴 [확장 프로그램] → [Apps Script]
 2) 기본으로 들어 있는 코드(function myFunction...)를 모두 지우고
    docs/google-apps-script-consult.js 의 내용을 전부 붙여 넣기
 3) 14번째 줄을 수정:
      const SPREADSHEET_ID = 'YOUR_SPREADSHEET_ID';
            ↓
      const SPREADSHEET_ID = '1단계에서 복사한 ID';
 4) 저장(Ctrl + S). 프로젝트 이름 예: "상담접수 API"


--------------------------------------------------------------------
3단계. 웹 앱으로 배포
--------------------------------------------------------------------
 1) 오른쪽 위 [배포] → [새 배포]
 2) 톱니바퀴(유형 선택) → [웹 앱]
 3) 설정
      - 설명          : 상담접수 v1
      - 다음 사용자로서 실행 : 나(본인 계정)
      - 액세스 권한이 있는 사용자 : 모든 사용자   ← 반드시 이 값
 4) [배포] → 권한 승인 창이 뜨면
      [액세스 승인] → 계정 선택 → "Google에서 확인하지 않은 앱" 화면이 나오면
      [고급] → [(프로젝트 이름)(으)로 이동(안전하지 않음)] → [허용]
    (본인이 만든 스크립트이므로 정상적인 절차입니다.)
 5) 표시되는 [웹 앱 URL]을 복사합니다.
      형식: https://script.google.com/macros/s/AKfy....../exec
    ※ 끝이 /exec 인 주소여야 합니다. (/dev 주소는 사용 불가)


--------------------------------------------------------------------
4단계. 웹 앱 동작 확인
--------------------------------------------------------------------
 복사한 웹 앱 URL을 브라우저 주소창에 붙여 넣어 열어 봅니다.
 아래와 비슷한 문구가 보이면 정상입니다. (이때는 시트에 아무것도 저장되지 않습니다.)
   {"success":true,"message":"시그니처과외 상담 접수 API가 동작 중입니다."}


--------------------------------------------------------------------
5단계. 사이트에 주소 넣기
--------------------------------------------------------------------
 js/script.js 맨 위 7번째 줄을 수정:
      const CONSULT_API_URL = "YOUR_GOOGLE_APPS_SCRIPT_WEB_APP_URL";
            ↓
      const CONSULT_API_URL = "https://script.google.com/macros/s/AKfy....../exec";
 ※ 따옴표는 그대로 두고 안쪽만 바꿉니다. 앞뒤 공백 없이 붙여 넣으세요.
 ※ 주소가 올바른 형식이면 상담 신청 페이지 오른쪽의
    "온라인 상담 접수 기능은 현재 준비 중입니다" 문구가 자동으로 바뀝니다.


--------------------------------------------------------------------
6단계. 실제 접수 테스트
--------------------------------------------------------------------
 1) consult.html 을 열고 테스트용 내용으로 신청서를 작성
    (페이지를 연 뒤 3초 이상 지나서 제출해야 합니다 — 스팸 방지 기능)
 2) "상담 신청이 접수되었습니다. 확인 후 안내드리겠습니다." 문구 확인
 3) 스프레드시트 '상담접수' 시트에 한 줄이 추가되었는지 확인
      접수시간 | 이름 | 연락처 | 학년 | 희망과목 | 수업방식 |
      거주지역/상세주소 | 기타요청 | 개인정보동의 | 접수페이지 | 브라우저정보
 4) 테스트 행은 확인 후 삭제하세요.


--------------------------------------------------------------------
Apps Script 코드를 나중에 수정했을 때 (중요)
--------------------------------------------------------------------
 코드를 저장만 해서는 웹 앱에 반영되지 않습니다.
 [배포] → [배포 관리] → 연필(수정) → 버전: [새 버전] → [배포]
 이렇게 하면 웹 앱 URL이 바뀌지 않으므로 js/script.js 는 고칠 필요가 없습니다.
 ※ [새 배포]를 다시 누르면 URL이 새로 생기므로 5단계를 다시 해야 합니다.


--------------------------------------------------------------------
문제 해결
--------------------------------------------------------------------
 ■ "상담 접수 주소가 아직 연결되지 않았습니다"가 계속 나옴
   → js/script.js 의 주소가 https://script.google.com/macros/s/.../exec 형식인지,
     따옴표 안에 공백이 없는지 확인. 브라우저 새로고침(Ctrl + F5).

 ■ "상담 접수 중 오류가 발생했습니다"가 나옴
   → 3단계의 '액세스 권한이 있는 사용자'가 [모든 사용자]인지 확인
   → 2단계의 SPREADSHEET_ID 를 바꿨는지 확인
     (바꾸지 않으면 spreadsheet_not_configured 오류로 저장되지 않음)
   → 코드를 수정한 뒤 '새 버전'으로 다시 배포했는지 확인
   → Apps Script 화면 왼쪽 [실행] 메뉴에서 doPost 실행 기록·오류 확인

 ■ 접수 성공 문구는 나오는데 시트에 행이 없음
   → SPREADSHEET_ID 가 다른 스프레드시트를 가리키고 있지 않은지 확인


--------------------------------------------------------------------
보안·개인정보 메모
--------------------------------------------------------------------
 - 입력값은 서버(Apps Script)에서 한 번 더 검사합니다.
   (필수 항목, 연락처 자릿수, 수업 방식 값, 글자 수 제한, 개인정보 동의 여부)
 - =, +, -, @ 로 시작하는 값은 앞에 ' 를 붙여 수식으로 실행되지 않게 저장합니다.
 - 숨김 칸(honeypot)에 값이 들어온 요청과 3초 안의 빠른 제출은 저장하지 않습니다.
 - IP 주소는 수집하지 않으며, 브라우저 console 에도 입력값을 출력하지 않습니다.
 - 웹 앱 URL 자체는 사이트 소스에 공개되는 값이라 비밀번호처럼 숨길 수 없습니다.
   스팸이 많아지면 Apps Script 쪽 검증을 강화하거나 새 배포로 URL을 교체하세요.
 - 실제 접수를 시작하기 전에 privacy.html 의 '확정 후 기재' 항목
   (보유 기간, 개인정보 보호책임자, 연락처 등)을 채우고,
   접수 데이터가 Google 서비스(Google Sheets)에 보관된다는 점을
   처리위탁·보관 관련 항목으로 추가할지 검토하세요.
 - 관리자 이메일 알림은 Apps Script 코드의 ADMIN_EMAIL 주석을 해제하면 사용할 수 있습니다.
   (처음 사용 시 메일 발송 권한 승인이 한 번 더 필요하며, 새 버전으로 재배포해야 합니다.)
